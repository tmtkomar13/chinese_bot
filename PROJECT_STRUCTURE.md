**Материал курса.** PDF остаётся на основном компьютере. В нём 30 пронумерованных уроков. В TSV каждая строка соответствует позиции в таблице «Новые слова и выражения» либо «Имена собственные». У вложенных слов есть свои карточки. Поля в порядке записи — постоянный ключ, урок, иероглифы, пиньинь, часть речи и перевод. Готовая SQLite рядом с TSV служит для первого переноса. На Windows её можно воспроизвести командой `python -m trainer import data/vocabulary.tsv`. При сверке откройте одноимённый урок в PDF и проверьте всю строку, особенно столбец тонов и продолжение таблицы на следующей странице.

**Пакет trainer.** `__main__.py` принимает команды `import`, `check`, `backup`, `gif-status`, `topic-status` и `run`. Путь к базе выбирается через `--db` либо `TRAINER_DB`. `storage.py` открывает SQLite с внешними ключами, выполняет миграции и отвечает за импорт и снимки. В `migrations/001.sql` описана исходная схема. Миграция 007 добавляет связи по урокам, выбор карточек и поля прогресса. В той же транзакции `storage.py` восстанавливает порядок и повторные вхождения по штатному TSV для существующих ключей. Миграция 008 добавляет поиск, очередь тем и триггеры для обновления разметки. При расширении схемы добавьте следующий файл с трёхзначным номером. При открытии базы приложение применяет миграции в транзакции и записывает номер в `PRAGMA user_version`.

**Логика занятий.** `training.py` формирует дневную подборку из открытых уроков и хранит сессии, оценки и текущие задания. До половины мест дневной подборки получают слова с последней ошибкой, остальные — карточки с наименьшим числом попыток. При равенстве порядок случаен. Если остальных слов не хватает, ошибки могут заполнить подборку до доступного размера. `review.py` выбирает карточки конкретного урока по порядку, случайно с приоритетом ошибок или по ручным отметкам, а затем вызывает тот же механизм создания сессии. Порядок карточек фиксируется до первого задания. Идентификатор занятия, номер карточки и факт открытия ответа проверяются при каждой оценке.

**Диалог.** `dialog.py` маршрутизирует действия, отображает текущую тренировку, настройки, список исключений и статистику. `screens.py` содержит общее меню и формат экрана. `review_dialog.py` показывает режимы урока, фильтр ошибок и ручной выбор. `search_dialog.py` сохраняет состояние поиска и обрабатывает выбор фильтров. `search.py` выполняет запросы к словарю и нормализует пиньинь, перевод и части речи. `vk.py` принимает события Bots Long Poll, проверяет владельца и личный диалог, извлекает действие из кнопки и отправляет ответы.

**Фоновые задачи.** `worker.py` обрабатывает очередь переводов и отдельно готовит GIF. `ai.py` вызывает Yandex AI Studio, содержит определения уровней, программную проверку кандидатов и отдельную проверку предложения моделью. `topics.py` использует тот же API в отдельном фоновом потоке, проверяет ключи и рубрики и сохраняет результаты партиями. `media.py` собирает GIF из локальных ресурсов `assets` и загружает документы в ВК. Версия оформления входит в ключи дискового кэша и таблиц вложений и повторов загрузки. `probe.py` проверяет внешние сервисы с настройками установленной службы.

## Как проходит нажатие

В режиме интерактивной страницы бот добавляет к адресу из `STROKES_PAGE_URL` слово и скорость. Браузер загружает `assets/index.html`, библиотеку Hanzi Writer и данные нужных знаков. `practice.js` ведёт один проход по контуру и выбранное число проходов по памяти. В каждом проходе ученик пишет все доступные знаки слова слева направо. Число повторов хранится в браузере. `speeds.json` задаёт скорость показа и для страницы, и для рендера GIF.

1. `VkBotLongPoll.check()` возвращает пакет событий и новую отметку времени. Бот отбирает входящие сообщения своего сообщества.
2. `accept` проверяет отправителя и получателя, регистрирует номер сообщения и передаёт действие в диалог. Этот номер уникален внутри личного диалога.
3. При запуске тренировки программа ищет текущую сессию. Для новой сессии сохраняет подборку, для существующей загружает первый незаконченный вопрос. Открытие ответа меняет флаг показа. Оценка меняет состояние задания и прогресс пользователя.
4. Ответ для отправки и новый курсор Long Poll попадают в ту же транзакцию, что и действия из пакета. После фиксации бот отправляет ответы по порядку. Успешно отправленный текст удаляется из очереди, номер обработанного сообщения остаётся. После сбоя отправка повторяется с тем же `random_id`.
5. После последнего слова и связанного с ним задания диалог суммирует оценки данной сессии. Общая статистика берётся из долговременного прогресса.

## Хранение данных

| Таблица | Содержимое и связи |
| --- | --- |
| `cards` | Текст карточки, транскрипция, перевод, необязательная часть речи и первый доступный урок. Первичный ключ берётся из TSV и остаётся прежним после исправления текста. |
| `lesson_cards` | Связь карточки с уроком и позиция в порядке TSV. Один ключ может находиться в нескольких уроках. |
| `learners` | ID пользователя, открытый урок, размер подборки, напоминания, задания на перевод, режим и скорость анимации. |
| `progress` | Одна строка на пару пользователь–карточка. Хранит попытки, ошибки, последнюю оценку и время, признак исключения и версию отметки. Версия защищает возврат слова старой кнопкой. |
| `sessions` | Пользователь, тип тренировки, дата, выбранный урок при повторении и признак окончания. У каждого пользователя может быть только одна активная сессия. |
| `tasks` | Сессия, карточка, порядковый номер, показ ответа и оценка. Сохраняет фазу перевода, запрошенный уровень, предложение с фактическим уровнем и разрешённые иероглифы. |
| `review_state`, `review_selection` | Выбранный урок, переключатель ошибок, режим ручного выбора, страница и отмеченные карточки. |
| `search_states` | Открытый экран, активные условия, выбранный для ввода фильтр и страница. Готовые переводы ждут в `tasks`, пока открыт поиск. |
| `card_topics`, `topic_jobs` | Принятые рубрики и очередь разметки с числом сбоев и временем следующей попытки. |
| `vk_messages` | Идентификаторы обработанных входящих сообщений. |
| `outbox` | Ответы диалога, напоминания и результаты фоновых заданий. Номер записи служит постоянным random_id. |
| `jobs`, `translation_attempts` | Незаконченные фоновые операции и история проверок. |
| `reminders_sent`, `media` | Журнал дневных напоминаний и идентификаторы документов ВК. |
| `media_retry` | Время следующей попытки и число неудач при подготовке версии GIF. |
| `vk_cursor` | Последняя принятая позиция Long Poll для сообщества. После переподключения используются эта позиция и сохранённая очередь. |

«Вспомнил» и «Не вспомнил» увеличивают попытки. Вторая оценка увеличивает и ошибки. «Точно знаю» завершает задание и исключает слово, сохраняя прошлые оценки. Возврат снимает отметку. Результаты занятий, сохранённая очередь и настройки пользователя не входят в обновление словаря.

## Установка и эксплуатация

Для обновления действующего бота используйте `deploy/from-windows.ps1 -Update`. Скрипт передаёт на Debian новую версию приложения вместе с каталогом `assets` и запускает `deploy/update.sh`. Для раздачи страницы в домашней сети отдельно настраивается служба `chinese-trainer-page.service`. Её полный текст и команды запуска приведены в разделе [«Запуск страницы на нетбуке с Debian»](README.md#запуск-страницы-на-нетбуке-с-debian).

`deploy/from-windows.ps1` собирает переносимый архив без учебника и окружения Windows, передаёт его на выбранный SSH-хост и запускает `deploy/install.sh` в терминале с вводом паролей. Установщик проверяет параметры ВК и записывает их в `/etc/chinese-trainer.env`. Образец имён переменных находится в `bot.env.example`.

На Debian код и виртуальное окружение находятся в `/opt/chinese-trainer`, рабочая база — в `/var/lib/chinese-trainer/trainer.sqlite3`. Служба `chinese-trainer.service` запускает бота при загрузке и перезапускает при сбое. Журнал доступен через `journalctl -u chinese-trainer`. Таймер `chinese-trainer-backup.timer` запускает одноразовую службу `chinese-trainer-backup.service`, которая хранит до семи дневных снимков в `/var/lib/chinese-trainer/backups`. Для последующих правок словаря переносится TSV, затем выполняется импорт в рабочую базу.

`README.md` содержит сценарии работы, команды настройки ВК, первого запуска, обновления и восстановления. Тесты используют временные SQLite и подменяют внешние сервисы. `test_review.py` проверяет копию стартовой базы, повторный импорт и три режима, `test_search.py` — комбинации фильтров и восстановление фоновой разметки, `test_v2.py` — состояние дневной тренировки и переводы, `test_gif.py` — все три скорости и старые вложения. Для проверки рендера укажите `CHROMIUM_PATH`. `.gitignore` исключает окружение, секреты, временные материалы и журнальные файлы SQLite.

## Где расширять

При приёмке `deploy/check-live.py` наблюдает за реальной тренировкой, перезапускает службу после первой оценки и сверяет результат завершённой сессии с ежедневным снимком. Из PowerShell его запускает `deploy/from-windows.ps1 -CheckTraining`.

- Новую команду или кнопку добавляйте в `dialog.py`. Для новой операции над занятиями вызывайте её из `training.py`, чтобы консольный или другой интерфейс мог работать с той же логикой.
- Новый алгоритм повторения подключайте на этапе выбора карточек. Сохраняйте выбранную последовательность в `tasks`, чтобы перезапуск продолжал уже выданную тренировку.
- Настройки напоминаний проверяются при каждом возврате из Long Poll, включая пустые ответы. Дата рассчитывается для Europe/Moscow.
- Для нескольких владельцев расширьте проверку доступа в `vk.py` и доставку ответов нужным адресатам. Прогресс и тренировки уже привязаны к пользователю.
- При изменении набора модулей, таблиц или путей развёртывания обновите этот документ вместе с кодом.

Для будущих версий предусмотрены фильтры словаря по тону и числу черт, классификация по ключам иероглифов, избранное, тренировки по теме, интервальные повторения и статистика освоения по урокам.
