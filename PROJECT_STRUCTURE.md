# Устройство тренажёра

## Файлы

```text

├── trainer/

│   ├── __main__.py
│   ├── storage.py
│   ├── migrations/001.sql
│   ├── training.py
│   ├── dialog.py

├── tests/test_trainer.py

├── .gitignore
├── README.md
└── PROJECT_STRUCTURE.md
```

**Материал курса.** PDF остаётся на основном компьютере. В нём 30 пронумерованных уроков. В TSV каждая строка соответствует позиции в таблице «Новые слова и выражения» либо «Имена собственные». У вложенных слов есть свои карточки. Поля в порядке записи — постоянный ключ, урок, иероглифы, пиньинь, часть речи и перевод. Готовая SQLite рядом с TSV служит для первого переноса. На Windows её можно воспроизвести командой `python -m trainer import data/vocabulary.tsv`. При сверке откройте одноимённый урок в PDF и проверьте всю строку, особенно столбец тонов и продолжение таблицы на следующей странице.

**Пакет trainer.** Файл `__init__.py` обозначает пакет. `__main__.py` принимает команды `import`, `check`, `backup` и `run`. Путь к базе выбирается через `--db` либо `TRAINER_DB`. `storage.py` открывает SQLite с внешними ключами, выполняет миграции и отвечает за импорт и снимки. В `migrations/001.sql` описана исходная схема. При её расширении добавьте следующий файл с трёхзначным номером. При открытии базы приложение применяет новые миграции в транзакции и записывает номер в `PRAGMA user_version`.

**Логика занятий.** `training.py` выбирает из открытых уроков до десяти разных написаний, исключая отмеченные как известные. До половины мест получают слова с последней ошибкой, остальные — карточки с наименьшим числом завершённых попыток. При равенстве порядок случаен. Если остальных слов не хватает, ошибки могут заполнить подборку до доступного размера. Выбранная последовательность фиксируется до первого задания. Здесь же проверяются идентификатор занятия, номер текущего задания и факт открытия ответа.

**Диалог.** `dialog.py` переводит действия в операции тренировки и возвращает текст с рядами кнопок. В нём находятся меню, выбор урока, список исключений со страницами и статистика. `vk.py` принимает события Bots Long Poll, проверяет владельца и личный диалог, извлекает действие из кнопки и отправляет ответ. Единственная внешняя библиотека приложения зафиксирована в `requirements.txt`.

## Как проходит нажатие

1. `VkBotLongPoll.check()` возвращает пакет событий и новую отметку времени. Бот отбирает входящие сообщения своего сообщества.
2. `accept` проверяет отправителя и получателя, регистрирует номер сообщения и передаёт действие в диалог. Этот номер уникален внутри личного диалога.
3. При запуске тренировки программа ищет текущую сессию. Для новой сессии сохраняет подборку, для существующей загружает первый незаконченный вопрос. Открытие ответа меняет флаг показа. Оценка меняет состояние задания и прогресс пользователя.
4. Ответ для отправки и новый курсор Long Poll попадают в ту же транзакцию, что и действия из пакета. После фиксации бот отправляет ответы по порядку. Успешно отправленный текст удаляется из очереди, номер обработанного сообщения остаётся. После сбоя отправка повторяется с тем же `random_id`.
5. После десятого задания или последнего доступного слова диалог суммирует оценки данной сессии. Общая статистика берётся из долговременного прогресса.

## Хранение данных

| Таблица | Содержимое и связи |
| --- | --- |
| `cards` | Текст карточки, транскрипция, перевод, необязательная часть речи и первый доступный урок. Первичный ключ берётся из TSV и остаётся прежним после исправления текста. |
| `learners` | Числовой ID пользователя и последний открытый урок, по умолчанию 13. |
| `progress` | Одна строка на пару пользователь–карточка. Хранит попытки, ошибки, последнюю оценку повторения, признак исключения и версию отметки. Версия защищает возврат слова старой кнопкой. |
| `sessions` | Принадлежность тренировки пользователю и признак окончания. У каждого пользователя может быть только одна активная сессия. |
| `tasks` | Ссылка на сессию и карточку, порядковый номер, показ ответа и оценка. По первой строке без оценки восстанавливается позиция. |
| `vk_messages` | Идентификаторы обработанных входящих сообщений и ожидающие доставки ответы. Внутренний ID служит постоянным ключом повторной отправки. |
| `vk_cursor` | Последняя принятая позиция Long Poll для сообщества. После переподключения используются эта позиция и сохранённая очередь. |

«Вспомнил» и «Не вспомнил» увеличивают попытки. Вторая оценка увеличивает и ошибки. «Точно знаю» завершает задание и исключает слово, сохраняя прошлые оценки. Возврат снимает отметку. Результаты занятий, сохранённая очередь и настройки пользователя не входят в обновление словаря.

## Установка и эксплуатация

`deploy/from-windows.ps1` собирает переносимый архив без учебника и окружения Windows, передаёт его на выбранный SSH-хост и запускает `deploy/install.sh` в терминале с вводом паролей. Установщик проверяет параметры ВК и записывает их в `/etc/chinese-trainer.env`. Образец имён переменных находится в `bot.env.example`.

На Debian код и виртуальное окружение находятся в `/opt/chinese-trainer`, рабочая база — в `/var/lib/chinese-trainer/trainer.sqlite3`. Служба `chinese-trainer.service` запускает бота при загрузке и перезапускает при сбое. Журнал доступен через `journalctl -u chinese-trainer`. Таймер `chinese-trainer-backup.timer` запускает одноразовую службу `chinese-trainer-backup.service`, которая хранит до семи дневных снимков в `/var/lib/chinese-trainer/backups`. Для последующих правок словаря переносится TSV, затем выполняется импорт в рабочую базу.

`README.md` содержит команды настройки ВК, первого запуска, обновления, восстановления, настройки крышки и проверки после перезагрузки. `tests/test_trainer.py` выполняет сценарии на временных копиях подготовленной базы. Тест транспорта получает реальные объекты событий библиотеки с локальными тестовыми данными. `.gitignore` исключает окружение, секреты, временные материалы и журнальные файлы SQLite.

## Где расширять

При приёмке `deploy/check-live.py` наблюдает за реальной тренировкой, перезапускает службу после первой оценки и сверяет результат завершённой сессии с ежедневным снимком. Из PowerShell его запускает `deploy/from-windows.ps1 -CheckTraining`.

- Новую команду или кнопку добавляйте в `dialog.py`. Для новой операции над занятиями вызывайте её из `training.py`, чтобы консольный или другой интерфейс мог работать с той же логикой.
- Новый алгоритм повторения подключайте на этапе выбора карточек. Сохраняйте выбранную последовательность в `tasks`, чтобы перезапуск продолжал уже выданную тренировку.
- Для ежедневной рассылки добавьте настройки времени и размера занятия в следующей миграции и отдельный планировщик. Он может вызывать ту же операцию запуска тренировки.
- Для нескольких владельцев расширьте проверку доступа в `vk.py` и доставку ответов нужным адресатам. Прогресс и тренировки уже привязаны к пользователю.
- При изменении набора модулей, таблиц или путей развёртывания обновите этот документ вместе с кодом.
